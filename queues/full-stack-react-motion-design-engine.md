# Full-Stack React & Motion Design Engine Queue

**Trigger:** review or build a React/TypeScript interface, improve UI/UX, refine responsive behavior, add purposeful animation, or assess frontend architecture and motion accessibility.

## Copy-ready prompt

> Use the `full-stack-react-motion-design-engine` skill. Inspect the actual repository, framework, routes, components, state/data flow, design tokens, dependencies, tests, accessibility setup, and deployment boundaries before changing anything. Translate the request into observable acceptance criteria and preserve existing product, API, CMS, authentication, and route behavior.
>
> Review visual hierarchy, layout, spacing, typography, contrast, density, responsive behavior, navigation, states, and consistency. Separate usability defects and accessibility failures from subjective design preferences. For React and TypeScript, prefer typed reusable components, project conventions, stable contracts, and targeted changes over speculative rewrites.
>
> For motion, explain the user purpose, choose CSS/Web Animations/an existing library based on evidence, prefer performant transform/opacity changes, preserve interruption and keyboard access, and honor `prefers-reduced-motion`. Avoid scroll hijacking, excessive parallax, autoplay audio, gratuitous effects, and animation that compromises reading or performance.
>
> Run available lint, type, unit, integration, accessibility, visual, and build checks. Report exact commands and results, mark unavailable checks NOT VERIFIED, review the final diff, and do not deploy or change production settings without explicit authorization.
