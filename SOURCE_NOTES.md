# Source notes and curation

This queue was assembled from the files in the user-provided Drive folder. The repository contains newly organized, generalized prompts; it does **not** copy the original research files, skill archive, or project archive wholesale.

## Source materials reviewed

- `radar-meta.skill` — RADARMeta skill and its references on intelligence modes, monitoring, and following hygiene.
- `radar-skill-inventory.txt` — existing skill inventory, including agent, app development, code language, debugging, Lovable/vibecode, authorized product study, market intelligence, and web development.
- `UNIVERSAL AGENT ARCHITECT research notes.md` — agent contracts, orchestration, state, approvals, and verification.
- `AGENT BRAIN research notes.md` — tool guardrails, human review, resumability, and side-effect controls.
- `MARKET INTELLIGENCE & BROKER BRAIN research notes.md` — SEC filings, point-in-time data, and concentration risk.
- `LOVABLE _ VIBECODE BRAIN research notes.md` and duplicate `(1)` — builder/backend inspection and generated-code verification; duplicate concepts consolidated.
- `APP DEV BRAIN research notes.md` and duplicate `(1)` — product workflow, authorization, RLS, webhooks, and integration safety; duplicate concepts consolidated.
- `DEBUG BRAIN research notes.md` — incident response, evidence logs, safe error handling, and regression testing.
- `WEB DEV BRAIN research notes.md` — WCAG 2.2, OWASP ASVS, verification, and repository portability.

## Deliberately excluded

`radar-release-portal.zip` is a separate application project, not a queue/skill source. It was inspected as an archive listing but not copied into this repository. Original Drive files remain unchanged. No Drive file or folder was modified.

## Editorial decisions

- Combined the repeated app-development and vibecoding notes instead of creating duplicate queue entries.
- Preserved platform-agnostic prompts so they can be loaded by any agent as plain Markdown; only the optional RADARMeta skill uses a conventional `SKILL.md` front matter.
- Used the source research as design input, not as a claim that the repo's instructions grant access to any service or that referenced external documentation has been re-checked live.
- Kept financial research analytical by default and separated recommendations from trading actions.
